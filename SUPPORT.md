# Self-hosted issues and support

Use [GitHub Issues](https://github.com/LikaloLLC/docsie-self-hosted/issues/new/choose)
for reproducible bugs, installation and upgrade problems, feature requests, and
documentation improvements related to Docsie Self-Hosted.

## Issue rules

1. Search existing issues and read the documentation for your release. Add useful
   evidence to an existing report when it describes the same problem.
2. Open one issue per problem. Give it a specific title, describe the user impact,
   and explain the expected and actual behavior.
3. Include the release or commit, relevant image versions, deployment environment,
   and minimal reproduction steps. Synthetic sample content is best.
4. Review every attachment and log excerpt before posting. Never share passwords,
   API tokens, license keys, kubeconfigs, Terraform state, rendered Secrets,
   customer documents, personal data, or private infrastructure details.
5. Be respectful. Disagreement and direct feedback are welcome; harassment,
   personal attacks, spam, and repeated promotional posts are not.
6. Describe observed results accurately. A chart rendering successfully, pods
   becoming ready, and a working user workflow are different evidence.

## Choose the right channel

- **Bugs and installation problems:** use the relevant issue form. Application
  problems encountered in a self-hosted installation are welcome; maintainers
  may route a fix to the application's private source repository.
- **Feature requests:** explain the problem and desired result. Opening or
  accepting an issue does not promise implementation or a release date.
- **Security vulnerabilities:** follow [SECURITY.md](SECURITY.md) and contact
  Docsie privately. Do not publish exploit details in this tracker.
- **Billing, licensing, account access, or customer-specific investigations:**
  use [Docsie support](https://www.docsie.io/support/). Public issues are not an
  emergency support channel. Contracted support follows your agreement.

## How issues are handled

Maintainers may request a smaller reproduction, ask for missing version details,
link duplicates, or redirect reports outside this repository's scope. Include a
link to the original issue when following up elsewhere. When a fix is available,
its release or commit and the verification performed should be recorded.

An issue may be closed when it is resolved, duplicated, outside scope, or cannot
be investigated with the information available. Provide new evidence when
requesting that a closed report be reconsidered. Preview availability does not
imply a production support commitment or a guaranteed response time.

AI-assisted reports and contributions are welcome. The submitter must check
commands, claims, links, and attachments and take responsibility for their accuracy.
